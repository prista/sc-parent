# Практическое задание: применяем контекст-инжиниринг

> В этом задании мы нацелимся не на получение идеального ответа от ИИ, а потренируем мышление через контекст — не через одиночный промпт.

## Шаг 1. Описываем минимальный AGENTS-файл для учебного проекта

Представьте, что у вас есть небольшой учебный проект (например, CRM-система или REST API для управления клиентами). Составьте краткий текстовый документ (10–15 строк), который рассказал бы ИИ:

- что делает система,
- какой стек используется,
- какие есть архитектурные правила,
- какие типы задач вы планируете решать с помощью ИИ (ревью, генерация тестов, рефакторинг).

*Пример заполненного AGENTS-файла* — @agents.md

## Шаг 2. Использовать этот текст как контекст в промпте

Возьмите одну конкретную задачу, которую вы хотите решить с помощью ИИ — например:

- «добавить пагинацию на списке клиентов»
- «реализовать кэширование профиля клиента»
- «добавить валидацию DTO с помощью Bean Validation»
- «настроить Circuit Breaker для внешнего API»

Сформулируйте промпт по схеме **Контекст → Задача → Формат → Ограничения**, где контекстом будет служить ваш «AGENTS-файл».

*Пример промпта на основе AGENTS-файла* — @config/prompts/cursor-based-pagination.md

## Шаг 3. Составить промпт

Используя ваш AGENTS-файл как основу, составьте промпты для следующих задач:

- Добавить кэширование через `@Cacheable` с Redis.
- Настроить Spring Security с JWT-аутентификацией.
- Интегрировать Kafka producer для событий создания клиента.
- Добавить Circuit Breaker (Resilience4j) для вызова внешнего API.
- Написать интеграционные тесты с Testcontainers.

## Шаг 4. Провести хотя бы один цикл допромптинга

После первого ответа ИИ:

- оцените, насколько он соответствует контексту и ограничениям;
- уточните промпт: добавьте недостающие ограничения, скорректируйте формат;
- запросите улучшенную версию решения.

### Примеры допромптинга

**Уточнение решения:**

> В предложенном решении кэширования не учтена инвалидация при обновлении клиента.
> Добавь `@CacheEvict` в метод `updateCustomer` и покажи, как настроить TTL в `application.yml`.
> Также добавь модульный тест с Mockito для проверки, что кэш инвалидируется.

**Смена фокуса:**

> Теперь добавь AOP-аспект для логирования всех вызовов методов сервисного слоя.
> Логируй: имя метода, аргументы, время выполнения, результат (успех/ошибка).
> Используй `@Around` и MDC для идентификатора корреляции.

## Дополнительное задание по допромптингу

Потренируйтесь в допромптинге на следующих сценариях:

- **Уточнение архитектурных решений:** попросите ИИ предложить решение, затем уточните, почему выбран именно этот паттерн, какие есть альтернативы и в чём их компромиссы.
- **Добавление требований безопасности:** после получения базового решения попросите добавить проверки авторизации через `@PreAuthorize`, валидацию входных данных, защиту от SQL-инъекций.
- **Оптимизация производительности:** получите рабочее решение, затем попросите проанализировать узкие места и предложить оптимизации (`@EntityGraph`, пакетные операции, пул соединений).
- **Расширение функциональности:** начните с простой задачи, затем итеративно расширяйте требования: добавьте кэширование, затем метрики Micrometer, затем распределённую трассировку, затем обработку ошибок через `@ControllerAdvice`.
- **Рефакторинг с сохранением поведения:** попросите переписать код в более читаемом виде или применить паттерн проектирования, но с требованием сохранить все существующие тесты зелёными.

В каждом случае обратите внимание на то, как меняется качество ответа после уточнений и как вы учитесь формулировать более точные запросы.
