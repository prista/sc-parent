# Игнорирование нефункциональных требований

ИИ часто предлагает решение, которое работает в изоляции, но неприемлемо в конкретном проекте из-за производительности, безопасности или наблюдаемости.

## Типичные проблемы

- Проблема N+1 запросов для больших наборов данных.
- Квадратичная сложность алгоритма.
- Блокирующие операции в реактивном контексте.
- Небезопасное хранение секретов (хардкод).
- Отсутствие обработки таймаутов и retry-политики.
- Отсутствие логирования и метрик для мониторинга.

## Как действовать

Явно указывайте нефункциональные требования — например:

- «Таблица содержит 10 млн записей, нужен эффективный запрос (efficient query) с использованием индексов».
- «Добавь структурное логирование (SLF4J с MDC) и метрики Micrometer».
- «В решении должна быть плавная деградация при недоступности внешних API (Circuit Breaker через Resilience4j)».
- «Это WebFlux-контекст, все операции ввода-вывода должны быть неблокирующими».
